# Vaultline — Express 5 Upgrade Guide

> **Current state (as of this writing):** Express `^4.18.2` installed.  
> Three of four confirmed breaking changes have been patched. The app is
> Express 5–ready for startup and GET routes. One silent regression remains.

---

## What has already been fixed

These changes are in `patient/src/` and are **forward-compatible** — they work
correctly on Express 4 today and will continue to work on Express 5.

### 1. `app.del()` → `app.delete()` · `src/app.js`

**Why it mattered:** `app.del()` was an Express 4 alias for `app.delete()`.
Express 5 removed it entirely. Calling it at startup caused an immediate
`TypeError: app.del is not a function`, which prevented the server from starting.

**Fix applied:** Renamed to `app.delete()`.

---

### 2. `app.use('*', ...)` → `app.use('/*', ...)` · `src/app.js`

**Why it mattered:** Express 5 upgraded `path-to-regexp` from v0 to v8. In v8,
a bare `*` wildcard is invalid (not a named capture). Express 5 throws a
`PathError: Missing parameter name` at startup — again, before any request.

**Fix applied:** Changed to `'/*'`, which is the shortest valid catch-all
accepted by both Express 4 and Express 5.

---

### 3. `req.param()` → inline lookup · `src/routes/invoices.js`, `src/routes/clients.js`

**Why it mattered:** `req.param(name)` was a convenience helper removed in
Express 5 (`TypeError: req.param is not a function`). It was wrapped in a
`legacyLookupParam()` helper and called on every GET-by-id request.

**Fix applied:** Replaced the body of `legacyLookupParam()` with an inline
equivalent that checks `req.params`, `req.body`, and `req.query` in the same
order Express 4 used.

---

## What still needs to be done (residual risk)

### 4. `res.json(body, status)` — silent status regression · **MUST FIX before upgrading to Express 5**

**Files:**
- `src/routes/invoices.js:69` — `router.post('/', ...)` response
- `src/routes/clients.js:49` — `router.post('/', ...)` response

**What it does today (Express 4):** Express 4 already emits a deprecation warning
in stderr for this pattern. The two-argument form `res.json(body, status)` still
*works* on Express 4.

**What it does on Express 5:** The second argument is silently ignored. Both
`POST /api/v1/invoices` and `POST /api/v1/clients` will return **HTTP 200** instead
of **201**. No crash, no error — just the wrong status code. Any client relying on
`201 Created` to distinguish creates from updates will break silently.

**Verified error output (Express 5.2.1):**
```
HTTP status received: 200 (should have been 201)
Response body: {"data":{"id":"123"}}
BREAK TYPE: Silent — wrong status code returned to caller
```

**Fix — two lines, mechanical:**
```diff
// src/routes/invoices.js, line 69
- res.json({ data: invoice }, 201);
+ res.status(201).json({ data: invoice });

// src/routes/clients.js, line 49
- res.json({ data: client }, 201);
+ res.status(201).json({ data: client });
```

This is the only remaining blocker. After this fix, `patient/` is fully
Express 5 compatible. Then:

```bash
# Switch package.json to Express 5
npm install express@^5 --prefix patient

# Run the full test suite
npm test --prefix patient
```

## Quick reference — what changed in Express 5 that matters here

| Pattern | Express 4 | Express 5 | Fix |
|---------|-----------|-----------|-----|
| `app.del()` | alias for `app.delete()` | **Removed** (TypeError) | Use `app.delete()` |
| `app.use('*', ...)` | valid glob | **Removed** (PathError) | Use `app.use('/*', ...)` |
| `req.param(name)` | lookup helper | **Removed** (TypeError) | Check `req.params`/`req.body`/`req.query` directly |
| `res.json(body, status)` | deprecated, works | Silent — status ignored | Use `res.status(n).json(body)` |
| 4-arg error handler `(err, req, res, next)` | required | **Still required** | No change needed |
| `router.delete()` | works | works | No change needed |
| `express.json()` / `express.urlencoded()` | works | works | No change needed |
